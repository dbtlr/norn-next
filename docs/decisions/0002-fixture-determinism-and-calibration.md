# 0002 — a generated tree is a function of `(profile, seed)`, and its realism is calibrated deliberately

Measurement needs a subject that does not move. `norn-fixtures` is that
subject: a deterministic Markdown-vault generator that turns a named profile
and a seed into a tree of documents, and nothing else into anything. Counters,
plan assertions, memory bars, resolution behaviour and the soak lane all
measure against trees it produces, so two properties are load-bearing at once —
the tree has to be **reproducible**, or a measurement compares two different
worlds; and it has to be **realistic**, or the measurement is precise about a
world nobody lives in.

## The contract

**The same `(profile, seed)` produces the same tree, byte for byte, on every
run and on every machine.** Four commitments carry it:

- Every choice is a draw from a seeded generator, in a fixed order.
- No clock, environment variable, path, locale or hash-map iteration order
  reaches a generated byte. Frontmatter timestamps are offsets from a fixed
  base date.
- Arithmetic is integer throughout, so no rounding difference can move a byte
  between platforms.
- Profiles are compile-time constants, so the pair really is the whole input.

`digest::tree` reduces a whole tree to one value — every node's relative path,
kind and bytes, absorbed length-framed in sorted path order — and the
determinism suite generates each named profile twice into fresh directories and
requires the digests to agree. **That gate is green before anything depends on
this crate.**

**Changing the generator changes the trees it produces, and that is allowed.**
The contract is that a given build reproduces itself; the gate is what keeps it
so. A pool edit, a knob default or a change to the PRNG moves every tree, which
is a review cost this contract makes visible rather than one it forbids.

**The contract binds this crate's own profiles.** It makes no claim about a
tree any other program produced, and this generator is not a reproduction
mechanism for one.

**Realism is five knobs, each a seeded draw, each documented on its own type.**

| Knob | What it dials | Why it is a knob |
|---|---|---|
| Body length | A weighted long-tailed mixture of target byte lengths, plus heading spacing | Every per-byte cost, and every cost that is a function of the largest document rather than the average one |
| Ambiguity classes | How many file-name stems repeat, and how many documents share each — the class size `k` | Bare-stem resolution, and any bound on a candidate list, which is only proven by a class larger than the bound |
| Link density | Links per document, their forms, and the share naming nothing | Graph shape, backlink cost, and the behaviour of an unresolvable target |
| Directory shape | Depth, fan-out, skewed placement, and leaf names including non-ASCII and spaced ones | Walk cost scales with directories, and a uniform spread hides every cost that depends on a directory being large |
| Non-Markdown clutter | Attachments, exports, editor state, and directories holding no documents | A walk pays for them and a graph gains nothing from them, so a tree without them measures a walk that does not exist |

**Body length is long-tailed, and that is a correction rather than a
preference.** A body drawn as a bounded uniform of a few short paragraphs
averages about 230 bytes. A document in a real collection averages several
kilobytes, and the distribution is long-tailed: most are short, a large
minority are much longer than the median, and a few are enormous. The gap is
about twentyfold, and it is not cosmetic — a tree of tiny documents understates
every per-byte cost by that factor and has no upper tail at all, so the largest
document any measurement sees is small and the memory invariant cannot be
measured against it. The shipped mixture averages about 4.5 KiB with a tail
reaching 70 KiB, and the mean is asserted as arithmetic rather than left to
prose.

**Profiles are data, and the table is the whole set.** `tiny` and `small` are
scaffolding; `ambiguous` carries classes past the point a bounded candidate
list must truncate; `realistic` is the ~2k-document profile the per-PR gates
measure against; `soak` is the ≥5k-document profile the scheduled lane runs. A
profile is added by editing the table, which arrives as a reviewable diff.

**Calibration is an authored envelope, checked in, with its reasoning beside
it.** The probe reports a tree's shape statistics; `probe::CALIBRATION` states
the inclusive range each is expected to land in, and every entry carries a
`why`. The ranges are **authored**, not measured: no entry is derived from any
particular collection, and each is deliberately wide enough to describe
collections in general and narrow enough that the failure it exists to catch —
a generator drifting back toward uniformly small, uniformly shallow, uniformly
linked documents — moves a statistic clean out of range.

**Recalibration is a deliberate act.** The probe runs against any directory, a
real collection included, so replacing an authored range with a measured one is
a command followed by an edit to that table — a diff that says what changed and
on what grounds. Nothing recalibrates itself, and no statistic is read from an
environment the repository cannot see.

**The probe is a shape meter, not a parser.** It reads bytes and counts
patterns; it resolves no link, honours no code fence, and decides nothing about
what a frontmatter field means. Document syntax has an owner elsewhere, and a
second interpretation of it here would be a second grammar. Facts that need
intent rather than bytes — how many links were made to dangle, how large the
classes were built — are reported by the generator in its manifest, because the
generator knows them and no byte-level reading can recover them.

**The crate is a leaf with no dependencies at all.** The digest, the calendar
arithmetic, the PRNG and the argument parsing are in-crate, because a generator
that links a parser, a hasher or a random-number crate inherits that crate's
version drift into the trees every gate measures against.

**The largest profile's runs are soak-lane work.** The determinism and
calibration cases for the ≥5k profile are `#[ignore]`d with their reason
stated; the per-PR lane runs the smaller profiles and the ~2k one. Long-running
work belongs in the lane built for it.

## Consequences

- Anything that measures against a fixture tree names it by `(profile, seed)`
  and gets the same subject every time, which is what makes a counter
  assertion or a memory bar a statement about the program rather than about the
  day.
- A pool edit or distribution tweak that quietly shrinks documents fails the
  calibration gate instead of silently flattering every benchmark downstream.
- The envelope can only move by an edit somebody reads, so "we recalibrated"
  is never something that happened without anyone deciding it.
- Every generated tree changes when the generator changes. That is the price of
  the contract binding a build rather than a version, and it is paid knowingly.
- Realism is not asserted in prose. The claim is a set of numbers with reasons,
  and the gate is what makes it checkable.
- Three things are deliberately absent, and their absence is recorded in the
  crate: no vault configuration file, because that contract does not exist yet
  and guessing at it would put an invented schema into every measurement tree;
  no expected findings or codes, because this crate states what it generated
  and never what a program should conclude; and no symbolic links or
  filesystem exotica, which belong to the crate that owns filesystem semantics
  and are better built directly for the cases that need them.
